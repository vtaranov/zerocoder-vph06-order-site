# VPh06 - Atelier: администрирование, метрики и приоритеты заявок

Учебная работа Виктора Таранова, продолжение [VPh05](https://github.com/vtaranov/zerocoder-vph05-order-site). FastAPI, PostgreSQL и Nginx обслуживают публичную форму и панель `/admin`. Исходники содержат готовый интерфейс, миграцию VPh05, SQL с вымышленными заявками и тесты.

## Возможности

- JWT-вход в панель: пароль хранится в PostgreSQL как scrypt-хеш с солью. JWT HS256 действует 30 минут; проверяются срок, алгоритм, issuer, audience и существование администратора. Токен панели хранится в памяти вкладки, после обновления страницы нужен вход.
- Кнопка первой регистрации показывается только при отсутствии администратора. Для регистрации дополнительно нужен `BOOTSTRAP_TOKEN`. Сервер запрещает вторую регистрацию; ограничение singleton в БД защищает и от гонки двух запросов.
- Таблица услуг: добавление, редактирование, удаление. Услуга с заявками защищена от удаления. Каталог публичной формы загружается из БД.
- Заявки сортируются по рассчитанной оценке, показывают приоритет и открываются в подробной карточке с причинами оценки и рекомендацией отдела/персонального менеджера.
- Статистика сессий за сегодня, 7 и 30 дней: среднее, максимум, количество; карта координат курсора и счётчики кликов.
- Добровольная анонимная статистика: отдельный флажок на главной, отправка не чаще раза в секунду, только пока страница видима. Содержимое полей в статистику не попадает. Отключение флажка прекращает сбор и отправку новых данных; уже сохранённые данные остаются.
- Метрики сессии сохраняются независимо от отправки заявки. Повторы одного номера пакета не дублируют точки и клики. Пакет содержит до 2 нормализованных координат и 30 меток кликов; сессия хранит до 3600 точек и 1000 кликов.
- Никаких внешних модельных API, CDN, шрифтов и аналитических сервисов. Ранжирование выполняется кодом по описанным правилам.

## Запуск с нуля

Нужны Docker Engine + Compose, Node.js 24+ для сборки и действительный TLS-сертификат. Backend работает в Python 3.13 внутри Docker. Python 3 нужен также для генератора приватных настроек.

```sh
git clone https://github.com/vtaranov/zerocoder-vph06-order-site.git
cd zerocoder-vph06-order-site
python3 scripts/init-secrets.py --host your-server.example.com --email admin@example.com
cd frontend
npm ci
npm run build
cd ..
mkdir -p web
cp -R frontend/dist/. web/
docker compose -f docker-compose.yml -f compose.lock.yml up -d --build --wait --wait-timeout 180
```

Проверьте `.env`, особенно пути Certbot `live` и `archive`, `PUBLIC_HOST`, `HTTPS_PORT`, параметры PostgreSQL. `SECRET_KEY` и `BOOTSTRAP_TOKEN` генерируются независимо, `.env` исключён из Git. Не подставляйте примерные значения в реальное развёртывание. Инфраструктурные образы зафиксированы в `compose.lock.yml`; npm-зависимость Swagger UI - в `package-lock.json`, Python-зависимости - в requirements-файлах. Генератор отказывается перезаписывать существующий `.env`.

В новой БД таблицы создаются при первом старте. Откройте `https://your-server.example.com:18443/admin`. При пустой таблице `admins` нажмите «Зарегистрироваться», задайте логин/пароль длиной от 12 символов и введите ключ настройки `BOOTSTRAP_TOKEN`. После успешной регистрации кнопка исчезает. Для проверки регистрации и входа через API доступны `/api/auth/check`, `/api/auth/register`, `/api/auth/login`, `/api/auth/me`.

Первый администратор - единственная учётная запись этого учебного приложения; управление несколькими администраторами и восстановление пароля не реализованы. Переменная старого VPh05 `ADMIN_PASSWORD` больше не используется backend.

## Продолжение VPh05 и миграция

1. Сохраните прежние `.env`, Compose, Nginx, `web` и дамп PostgreSQL. Используйте прежний каталог и `COMPOSE_PROJECT_NAME`, чтобы сохранить тома.
2. Добавьте в прежний `.env` независимые случайные `SECRET_KEY` (минимум 32 символа) и `BOOTSTRAP_TOKEN`; `ENABLE_DOCS=false`.
3. Соберите фронтенд и новый образ backend до остановки прежнего сервиса.
4. Остановите только backend и выполните **один раз** транзакционную миграцию существующей БД:

```sh
docker compose stop backend
docker compose exec -T postgres sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < backend/migrations/006_metrics_and_admin.sql
docker compose -f docker-compose.yml -f compose.lock.yml up -d --build --wait
```

5. Зарегистрируйте первого администратора. Можно сохранить прежние логин и пароль VPh05: теперь проверяется их хеш в БД вместо Basic Auth.
6. После проверок остановите прежние инструменты, если они ещё работают:

```sh
docker compose --profile maintenance stop pgadmin registry
```

Миграция сохраняет старые заявки и метрики. У `behavior_metrics` появляется собственный PK, уникальный `session_id`, необязательная ссылка на заявку, время начала/обновления, тип компоновки и номер принятого пакета. Старые строки помечены `legacy`: участвуют в временной статистике, но их пиксельные координаты не смешиваются с новой нормализованной heatmap. Новые снимки метрик при отправке формы имеют `layout=application` и исключаются из агрегатов сессий, чтобы не учитывать одного посетителя дважды.

Повторный запуск миграции запрещён её форматом; сначала проверяйте наличие `session_id`. На новой пустой базе миграция не нужна. `create_all` не заменяет миграции существующих колонок.

## Приоритеты: явные правила

| Критерий | Баллы |
|---|---:|
| Сегодня, завтра, явно срочно или до 3 дней | 40 |
| До 7 дней | 25 |
| До 30 дней | 10 |
| Не срочно, срок не определён или непонятен | 0 |
| Бюджет / верхняя цена выбранной услуги | 0-30 |
| Размер компании: до 10 / 11-50 / от 51 сотрудника | 3 / 8 / 15 |
| Роль: сотрудник / руководитель | 3 / 10 |
| Количество в задаче: от 3 / от 10 | 5 / 10 |

Горячий лид: **от 65** баллов, средний: **35-64**, низкий: **до 35**. Сортировка по баллу убывает, при равенстве выше новая заявка. Для высокой оценки рекомендуется персональный менеджер; корпоративный отдел определяется размером компании/объёмом задачи.

Это учебная эвристика приоритета, а не модель вероятности сделки. Учитываются ограниченные русскоязычные формулировки относительных сроков и заданные размеры компании; абсолютные даты не разбираются. Пустые/непонятные значения не получают баллы за срочность. «Не срочно» проверяется до слова «срочно», число 13 дней не превращается в 3 дня. В карточке показаны все исходные критерии и баллы; решение остаётся за менеджером.

## Проверка 10 заявок

Сначала создайте услугу «Полировка» с диапазоном 15 000-45 000 ₽. Затем:

```sh
docker compose exec -T postgres sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < backend/scripts/seed-demo.sql
```

SQL добавляет 10 вымышленных заявок с `example.com`, не содержит заранее записанных статусов приоритета и безопасен для повторного запуска по уникальным тестовым контактам. Если услуги «Полировка» нет, записи не вставятся - проверьте число строк. Список проверочных примеров и ожидаемые метки находятся в `backend/tests/fixtures/leads.json`. На панели найдите `VPh06 /`: ожидаются **4 горячих, 3 средних, 3 низких**, в порядке убывания баллов. Откройте «Просмотр» для нескольких строк.

Для метрик включите согласие на главной, проведите на ней 2-3 минуты, двигайте мышью, меняйте услуги и нажимайте элементы. В панели откройте «Статистика пользователей». Показатели вычисляются по сессиям, а не по числу секундных запросов. «Сегодня» начинается в 00:00 Europe/Moscow; неделя и месяц - скользящие 7 и 30 дней по времени начала сессии. Координаты нормализованы к размеру всей страницы (0-1000) и сгруппированы по частоте, отдельно для узких и широких экранов. Это схематичная карта, без наложения снимка сайта.

## Безопасность и Swagger

Публикуется только HTTPS-порт Nginx: **18443 по умолчанию**, внутри контейнера - 443. На отдельном сервере можно задать `HTTPS_PORT=443`. Backend (8000), PostgreSQL (5432), pgAdmin и Registry не публикуют порты хоста. pgAdmin/Registry находятся в выключенном по умолчанию профиле `maintenance`; маршруты к ним отсутствуют в финальном Nginx. Данные их томов сохраняются. Watchtower сохраняет прежний scope `vph04`, backend для него не помечен; автоматическое обновление приложения не заявляется.

Закрытый TCP-порт не возвращает HTTP 403: проверяйте отказ/тайм-аут подключения и отсутствие PortBindings, а не HTTP-код. Сам прикладной API доступен по HTTPS через Nginx; каталог, форма, вход и метрики требуют публичных маршрутов. Нельзя гарантировать, что к публичному API обращается исключительно наш фронтенд. Административные операции требуют JWT; серверная валидация работает независимо от браузера. Лимит входа Nginx - 5 запросов в минуту с небольшим burst, лимит метрик - 2 запроса в секунду на IP.

В финальном режиме `ENABLE_DOCS=false`: Swagger, OpenAPI и статические файлы Swagger отключены. Nginx также блокирует их публичные маршруты. Для временной локальной проверки выставьте `ENABLE_DOCS=true`, пересоздайте backend и организуйте SSH-туннель, ограниченный localhost:

```sh
# На VPS узнайте внутренний адрес контейнера:
docker inspect vph04-backend-1 --format '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}'
# На своём компьютере подставьте найденный адрес:
ssh -N -L 127.0.0.1:18006:INTERNAL_BACKEND_IP:8000 user@your-server.example.com
```

Откройте `http://127.0.0.1:18006/docs`: выполните `/api/auth/login`, скопируйте `access_token` в Authorize → HTTPBearer и проверьте `/api/auth/me`. Не публикуйте токен и снимки Curl с Authorization. После проверки верните `ENABLE_DOCS=false`, пересоздайте backend и закройте туннель. Для другого `COMPOSE_PROJECT_NAME` имя контейнера будет отличаться.

## Автоматические проверки

```sh
cd frontend
npm ci
npm run build
cd ..
python3.13 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-lock.txt
cd backend
PYTHONPATH=. ../.venv/bin/python -m pytest -q
```

Тесты используют временную SQLite с foreign keys и отдельно проверяют JWT, singleton-регистрацию, CRUD и целостность, агрегирование метрик, повторные пакеты, 10 независимых примеров и разбор сроков, обработку отказа БД. GitHub Actions выполняет тесты и сборку. Проверка реального PostgreSQL, интерфейса, миграции и закрытых портов проводится дополнительно при развёртывании.

```sh
docker compose ps
docker compose logs --tail=100 backend
docker compose logs -f backend
docker compose exec -T nginx nginx -t
docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT id, application_id, layout, time_on_page, sequence FROM behavior_metrics ORDER BY id;"'
```

## Резервирование и ограничения

PostgreSQL использует прежний постоянный том. Не выполняйте `down -v` для обслуживания. Сохраняйте приватные настройки и внешние резервные копии, например `pg_dump`; секреты, дампы, реальные заявки, журналы и снимки не входят в репозиторий. Hook TLS рассчитан на прежний путь `/opt/vph04-orders`.

Статистика сессий достоверна в пределах передаваемых браузером значений; внешний отправитель способен подделать публичные метрики. Записи сессий автоматически не удаляются, хранение нужно ограничить при эксплуатации. Система не отправляет сообщения клиентам, не принимает оплату, не использует внешние LLM и не подменяет проверку менеджером. Распределённый антифрод, MFA, refresh-токены, многопользовательские роли и журнал действий администратора не реализованы.
